# v500 样本格式与 ABI 普查（2026-11-22）

> 样本：`<v500-sample>`（真名/路径见 `AGENTS.md` §1.2）
> 对照：`<v555-2>`（真名/路径见 `AGENTS.md` §1.1）
> 方法：解包 `pac/bn.ypf` 的 `ysbin/ysc.ybn`、`ysbin/ysv.ybn`、
> `ysbin/yscfg.ybn`，按字节/记录比较；不依赖 exe 版本字段的猜测。

## 1. 版本

- `<v500-sample>` 主 exe 的 ProductVersion：`0,500,0,0`，
  ProductName `YU-RIS Script Engine`；
- `ysbin/ysc.ybn`（`bn.ypf` 偏移 `0x3763`，csize=4115，zlib）：
  - `YSCM`，`version=500`，`count=121`。

## 2. YPF v500

- 文件头：`YPF\0`，version=500，entry_count=315，data_start=`0x3763`；
- 索引：Meta22（`u64 dataOffset + u32 payloadHash`），V500 名字长度表；
- `nameHash` 仍是 `murmur2(name, 0)`；
- `payloadHash` = **`xxh32(存储字节, seed=0)`**；
  - 抽验 `ysc.ybn`、`yst00034.ybn`、`yst00145.ybn`、`yscfg.ybn`、
    `yst00236.ybn`，5/5 与索引值相等；
  - 例：`ysc.ybn` stored 4115B，`xxh32=0x28137fc8`，索引
    `payloadHash=0x28137fc8`；
- 载荷是普通单段 zlib（`78 DA`），不是加密。

实现：`crates/yu-vfs/src/ypf.rs` 增加 `HashAlg::Xxh32`；校验时主算法不命中
再按 `xxh32` 裁决，命中才接受；旧 YPF 主算法命中后不会走回退。

## 3. YSCF v500

`ysbin/yscfg.ybn`（141B，解压后）：

```text
+0x00 "YSCF"
+0x04 u32 version=500
+0x10 u32 width=1920
+0x14 u32 height=1080
+0x18 u32 flag
+0x1C u8[8] image ext order
+0x24 u8[4] sound ext order
...
+0x48..+0x58 新增未知 dword 区
+0x58 u16 titleLen=51
+0x5A title（文件恰好在标题末尾闭合）
```

实现：`crates/yu-format/src/yscf.rs` 增加 `YscfLayout::V500`；旧 `New/Old/V292/V255`
候选与裁决逻辑不变。

## 4. v500 vs v555 ABI 普查

### 4.1 `ysc.ybn`（命令表）

- 两者文件长度均为 **11102B**，命令数均 **121**；
- 逐字节只有 **3 处差异**：
  1. `+0x04` 版本字段：500 vs 555；
  2. `GRADATION` 参数的 `kind` 字节：500=`7`，555=`3`；
- 121 条命令名、参数名、argc、flag 全部相同；
- 包含 `MOVIE2/MOVIE2END/MOVIE2INFO`、`SYSTEMMODE`、`COMPILEMODE`、
  `RELEASEMODE`、`PROJECTFOLDER`、`PRODUCT`。

### 4.2 `ysv.ybn`（系统变量 ABI）

- 只看系统槽 `0..999`：**1000/1000 完全一致**
  （kind/flag/file_id/ty/dims/init 全同）；
- 游戏自定义变量（`>=1000`）按作品不同：
  - v500：3388 条声明；
  - v555：3373 条声明；
  - 差异是作品变量，不是系统 ABI。

### 4.3 仍不同的格式层

- `yscfg.ybn`：v500 是 `V500` 布局（title @0x58），v555 是 `New`
  （title @0x4C）；
- YPF：v500 的 `payloadHash` 是 xxh32，v555 样本是 murmur2；
- handler 处理体尚未逐条对拍。

## 5. 结论

- 0.500 可归入 **121 槽命令表 + 0.495 系统 ABI 族**，与 v555 共享
  命令映射和系统变量 ABI 基础设施；
- 必须独立 `SemanticProfile`/profile 覆盖的点：
  - `GRADATION` 参数 kind（7 vs 3）；
  - 0.500 处理体差异（待 RE 普查）；
  - YSCF `V500`、YPF xxh32 等格式差异；
- **2026-11-24 更新**:处理体对拍后,0.500 归入 **555 商业族**
  (`SemanticProfile::is_v555_family`):`TEXT`/`CGINFO`/`VARINFO`/
  `RETURNCODE`/`GOSUB`/`RETURN`/`LET`/`VARACT`/`SAVE`/`LOAD` 与 v555
  同构;差异按版本/表能力覆盖:
  - `MOVIE2*`/`REGINFO` 在 0.500 是 29B 空桩;
  - `PRODUCT` 有 0.500 新增分支(COM=1/2/3、56/57、0x5dc1..0x5dc9);
  - `save_image` 仍精确 555(0.500 官方存档无 DNO=3 缩略图块);
  - `.ydg` 资产容器与 0.500 扩展码表(`1=bmp,2=png,5=ydg,6=webp`)。

  详见 `DIV-RT-079` 与 `DIV-GFX-093`。

## 6. 汉化方式（记录，暂不实现）

`<v500-sample>` 的汉化补丁是 <patch-group> 外挂：

- `winmm.dll` + `<patch-group>.ini` + `<patch-group>.chs`；
- `FileRedirect=1`，`ArchiveFile=<patch-group>.chs`，`Folder=<patch-group>`；
- 字体 Hook：补丁自带 TTF（文件名见游戏目录），`Charset=128`（Shift-JIS），
  `EnableFaceNameReplace=1`、`EnableCharsetReplace=0`；
- 不是改原版 YPF/数据层嵌入；内核需要通用 patch overlay 才能支持。

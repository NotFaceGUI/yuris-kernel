## 0. 一句话结论

**121 条命令的“分发表类别”在 6 个可分析构建上完全一致**(26 默认错误槽 /
7 共享空操作 / 88 真实处理体),但**处理体语义不是单一版本**:
2.1MB 族(样本 <v555-2>/<v555-3>/<v555-4>/<v555-5>)共享一套 TEXT/CSV/PRODUCT;
`<v555-pc>` 是一套近亲变体;`<v555-1>` 的 TEXT/CSV/CSVINFO/SOUNDINFO/FILEACT/PRODUCT
明显更大(独立实现)。当前内核主要按 2.1MB 族实现,已确认的硬差异集中在
`_STR`(<1000 槽)、`PRODUCT[COM=23/34/12]`、`CSV` 路由与 `TEXTINFO` 空签名;
图形 P0 仍未取证到可修的程度。

## 5. 系统变量与 `_STR`

### 5.1 ABI

`docs/formats/v555-sysvar-abi-measured.tsv` 已复核:本仓库六个 555 样本的
`ysv.ybn` 在 id 0..999 上与 0.495 ABI 逐字段相同(548 具名 + 452 保留);
作品全局从 1000 起。旧线记录的「v555 `@409` 是游戏变量」属于另一款样本
(<game-a>)的布局,不适用于本仓库六样本;不能据此推翻
本仓库的 ABI 结论,但说明 **555 各作 ysv 可不同**,仍需按作品 ysv 前缀校验。

### 5.2 `_INT`

官方 `0x44803c` 的 case 0x32(`0x448974`):

- 槽号 <1000 → 0;
- type 1 → 整数取值;type 2 → `FISTP` 前把 FPU 控制字置 `0xC00`
  (round toward zero,截断)再取整。

当前 `sysvar.rs` 的 `_INT` 用 `f as i64` 截断,与 `0xC00 + FISTP` 一致;
`<1000` 返回 0 也一致。**已对齐。**

### 5.3 `_STR`

官方字符串 getter `FUN_004213bc` 的 case 0x34(`_STR`)在 `param_5 < 1000`
时**不做任何事**(空串);`>=1000` 委托 `FUN_0044d66c`。但 `FUN_0044d66c`
在槽号 <1000 时先调用 `FUN_004213bc(slot, …)` 取**系统字符串变量**,再写回
变量表并返回指针。`FUN_004213bc` 的已知 case:

```text
0x0c _ARGV   0x0e _DROPFILE  0x34 _STR   0x37 _PSTR  0x3e _RSTR
0x45 _TSTR   0x67..0x6b(文本/字体路径类)
0x7a _TEXT   0x7b _TEXT_FLAG 0x7d _TASK  0x7f _CHR
0x80..0x83 _CGSET/_SOUNDSET/_TASKSET/_MENUSET
```

**当前实现的问题**:`_STR` 对槽号 <1000 直接返回空串(`sysvar.rs:412-431`),
没有走这组系统字符串变量。对本仓库已实现的 `_ARGV`/`_DROPFILE`/`_PSTR`/
`_RSTR`/`_TSTR`/`_CHR`/路径/`_TEXT`/`_TEXT_FLAG`,可以直接复用同名读取;
`_TASK`/`_CGSET`/`_SOUNDSET`/`_TASKSET`/`_MENUSET` 目前未实现,需按官方
case 或显式挂号。**这是已确认的语义缺口**,不是猜测。

## 6. 已确认的当前实现问题

### 6.1 `CSV` 路由

官方 `<v555-3>` CSV = `0x43c3a0`(1148B),真实 CSV 解析器:读 FILE、规范化
`/`→`\`、按 CRLF/CR/LF 与引号/逗号切单元格、写 LET。当前
`build_handler_table` 的判据是「有 LINE 或序号 != 7 → Csv」;v555 CSV 序号 7
且无 LINE,于是落到 `NoopEval`(`handlers/mod.rs:303-312`)。

- 证据:`docs/formats/v555-command-handlers-b02a4dc04ae.tsv` opcode 7;
  `DumpAllDecomp` 的 `0043c3a0_V555H_43c3a0.c`。
- 当前六款 555 语料 **CSV 使用 0 组**,所以是潜在缺陷,不是本轮黑屏主因。
- 修复:v555 序号 7 也走 `Csv`;0.495/0.479 保持 NoopEval。

### 6.2 `ALIAS` 路由

官方 ALIAS = `0x423168`(共享空操作,`xor eax,eax; ret`);当前
`build_handler_table` 不认这个名字,落 `HandlerKind::Unknown`
(`handlers/mod.rs:717-720`)。当前六款语料 ALIAS 使用 0 组,潜在缺陷。
修复:555 共享空操作清单加 `ALIAS`。

### 6.3 `PRODUCT[COM=23]` 只写了计数,缺长度数组

2.1MB 族的 `es_scenario_load.yst`(样本4 s60)pc36:

```text
PRODUCT | COM=23 | PINT=@3004 | PINT2=@3005 | LET=@2881
```

官方 `FUN_0045bcf8` 遍历源字符串数组(PINT2),把每个元素的**长度**写入
目标整数数组(PINT),直到空串;返回非空个数,并由调用方写入 LET。
当前 `product.rs` 只把 `last_text_lines` 写进 LET,**没有写 PINT 长度数组**;
对只读计数的调用方“碰巧”可用,但不是 1:1。

修复:按 `FUN_0045bcf8` 实现 PINT2→PINT 长度数组 + LET 计数。

### 6.4 `PRODUCT[COM=34]` 磁盘剩余空间未实现

2.1MB 族 `0x45c1d0` 是 `GetDiskFreeSpaceExA(path, &free, …)`,并把结果写
LET。当前 `product.rs` 把 34 列入「已取证但未实现」,报 `rt.cmd.unimplemented`。
静态计数:2.1MB 族(样本 2/3/4/5)各 6 组,<v555-1> 3 组,属于**实际使用**
分支。修复需要宿主磁盘查询端口;至少应写一个明确值而不是不写 LET。

### 6.5 `PRODUCT[COM=12]` 文件复制未实现

2.1MB 族 `0x45a70c` 打开源文件、建目标、复制、关闭,返回 0/-1;当前把
COM=12 当官方落空 no-op。样本 2/3/4/5 静态各 1 组。若该路径被执行,
当前会跳过复制。修复可复用 `FILEACT` 的 VFS 读写。

### 6.6 `PRODUCT` 其余已使用 COM

按 `docs/formats/v555-product-com-*.tsv`:

- 2.1MB 族:12,21,22,23,24,29,34,51,52,80,81;
- <v555-1>:34,51,52,80,81,90,10201,10205,21000;
- <v555-pc>:1001,10201,10205。

当前 51/52/80/81 同型 no-op 可接受;90/1001 在官方是条件回调/落空,当前
no-op 也基本可接受;10201/10205 是 Win32 文件对话框,21000 是 <v555-1> 的路径
查询(`FUN_0045c20c`),当前均挂未实现。10201/10205 属宿主 UI 适配,
21000 需补 LET 结果。

### 6.7 `TEXTINFO` 空签名

官方 `0x452d54` 只做参数装载后 `return 0`;v555 的 TEXTINFO 参数表为 0。
当前 `op_textinfo` 在缺 LET 时报告 `TEXTINFO 缺 LET 目标`
(`text.rs:204-229`)。六款语料 TEXTINFO 使用 0 组;仍应改为「无查询项即
返回 0,不报诊断」。

### 6.8 `SemanticProfile` 的 `>= 555`

`semantics.rs:111-131` 把 `version >= 555` 全部映射成 555 形态,并在测试里
把 556/600 断言成同一套。用户口径明确:**555 是独立商业分支**;556/600 没有
证据。改为精确 `version == 555`;其它版本按未取证处理(保留 legacy 或显式
Unknown),新增 556/600 不得继承 555 的回归。

### 6.9 TEXT 源回退与文件源顺序

<v555-1> 的 TEXT 1404B 在打开前尝试 4 个来源(4 个不同 open 函数);2.1MB 族/
<v555-pc> 的 837B 只走一个 `FUN_0040bcdd`。样本剧本自己在脚本里显式调用
`TEXT(FILE=base)`、`TEXT(FILE="sc_cn_"+…)`、`TEXT(FILE="sc_tw_"+…)` 做语言
回退(s60 pc1-3/6-8),所以脚本可见语义不一定依赖引擎的 4 源循环。当前
`open_asset` 的源顺序仍是 `v555-commercial.md §16.6` 的未裁决项;本轮不单方
翻转,但要把「TEXT 失败后是否推进 pc/让调用方回退」用 trace 核实。

## 11.7 编码真值:样本是 Big5,不是 GBK(2026-11-21 续)

### 11.7.1 官方引擎的静态 lead-byte 表

- `b3c02ab23bf`(`<v555-2>`)与 `b02a4dc04ae`(`<v555-3>`)的
  `DAT_0059b0c0`(256 B)实测:
  `0x81..=0x9F` + `0xA1..=0xFE` = 1,`0xA0`/`0xFF` = 0 ⇒ **Big5/CP950**。
  CP932 应为 `0x81..=0x9F`/`0xE0..=0xFC`;GBK 应为 `0x81..=0xFE`。
  证据:REA `read_bytes 0x59b0c0 len=256`(两构建同型)。
- 该表被 TEXT/GOSUB/变量遍历等 60+ 处引用;它是**构建的静态执行编码**。
  但游戏内还有语言选择入口(`ES.LANG.SET`,见 §11.7.3),**不能**用
  该表替代语言选择;语言切换时是否换表/换文本 codec 尚未取证。

### 11.7.2 语料自证

- ybn UI 字符串只有 Big5 能解:
  `A1 69 C5 40 A4 68 A1 6A` →「【護士】」;
  `A1 69 A4 73 A5 D0 A1 6A` →「【山田】」。
  CP932 解成半角片假名/乱码,GBK 在 0xA1 处非法。
- 场景文本按语言分目录且编码不同(同一 `saku_05_06.txt`):
  `scenario/` = CP932(5293 B)、`sc_cn_scenario/` = GBK(4665 B)、
  `sc_tw_scenario/` = Big5(4665 B)。
  `es_scenario_load` s60 pc1–3 把三者分别读入 `$2868/$2869/$2870`,
  再由脚本按语言选择;Big5 构建应选 TW 数组。

### 11.7.3 语言选择的代码证据(脚本侧)

- `ES.LANG.SET`(s26 pc0–22)按 `@53[1]`(语言号)分三支:
  - 0:`@1000=1,@1002=0,@1001=0`,`$1179[38][31]="cgsys/"`;
  - 1:`@1000=0,@1002=1,@1001=0`,`$1179[38][31]="cgsys_cn/"`;
  - 2:`@1000=0,@1002=0,@1001=1`,`$1179[38][31]="cgsys_tw/"`;
  然后 `es.BT.TASK.INIT`。
- 这是**游戏内可选语言**的真实入口:`\CSEL` → `ES.CSEL.SET`(s36
  pc113)→ `es_select2` → `ES.LANG.SET`;资源前缀随语言切换。
- 文本数组选择(s58 `es_scenario_label` pc81–88):
  - `@1002==1`(CN)→ `PRODUCT COM=22` 读 `$2872`;
  - 否则 `@1001==1`(TW)→ 读 `$2873`;
  - 否则(base/JP)→ 读 `$2871`。
  s60 pc10–19 把 `TEXT[FILE]` 的三份 `$2868/$2869/$2870` 拷到
  `$2871/$2872/$2873`;语言选择只换数组,不换引擎的静态 lead 表。
- 官方 `TEXT[FILE]`(b3c02 `0x452888`)是**字节拷贝**:按
  `DAT_0059b0c0` 的 lead 表跳过双字节、`/`→`\`、按 CRLF/CR/LF 切行,
  不做编码转换。因此选定语言的数组必须与构建的静态编码一致;
  多语言包若同一构建混用 CP932/GBK/Big5,引擎本身无法正确解析。
- 场景文本三数组 `$2868/$2869/$2870`(s60 pc1–3 `TEXT[FILE]`)与
  `@1000/@1001/@1002` / `ES.LANG` 的选择路径已由脚本给出;引擎侧
  没有按语言换 codec 的证据(静态表)。

### 11.7.4 本机对齐(通用能力,无 v555 特化)

- **未改 `PatchKind::Auto`**(主人裁决:auto 匹配是给别的汉化版本用的;
  本样本用显式 `PROBE_VM_PATCH=big5` 取证)。
- `probe_dialog` 不再写死 `script/text=Gbk`,改走
  `PatchSelection/PatchProfile`(显式 `big5|gbk|original`;Auto 原语义保留)。
- `PRODUCT[COM=22]` 词法器 `tokenize(line, codec)` 使用
  `script_text_codec` 的 lead 表;`VARINFO[SJISCODE]` 原本已按
  script codec;`decode_string_literal_with(codec)` 增加 Big5 用例

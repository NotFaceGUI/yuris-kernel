# DIV-GFX-065 · 固定管线过渡(`T/TA/TID`)的覆盖度模型:官方是「顶点 α 渐变 × mask」,不是阈值

- 状态:**open**(现象已定,公式待逐项对齐)
- 取证对象:官方 0.495 `yu-ris.exe`(sha256 `4f5eefa3…`),`FUN_00414ba4`
  (`0x414ba4`-`0x4171f0`)
- 现象(用户口径):官方过渡是**平滑半透明**;我们直接黑幕/硬边界
  (开幕时钟、开幕 logo、立绘退出都可见)

## 1. 我们现在怎么算

`yu_gfx::transition_coverage`:

```text
fade     = T / (256/(256/TA+128)) / 256
threshold= 1 - 2*fade
slope    = 30 + 70*fade
coverage = clamp(slope * (mask - threshold), 0, 1)
```

斜率 30..100 ⇒ 过渡带只有 1%–3%:mask 一旦跨过阈值就直接 0→1,
所以边界是硬的(用户看到的就是这个)。该式是 TA=128 的**校准拟合**
(残差 ≤8/255 于三个中点),不是官方算式。

## 2. 官方固定管线实际做了什么(REA 逐指令)

`FUN_00414ba4` 在双纹理分支(`0x415558` 之后)设置的状态:

```asm
; D3DRS_TEXTUREFACTOR = 0x3c,值 = 层 alpha << 24(只占 A 通道)
0x415645  PUSH [ESP+0x1b4] / PUSH 0x3c / CALL [vtbl+0xe4]      ; SetRenderState
; stage0
0x415667  SetTextureStageState(0, D3DTSS_COLOROP=1,   D3DTOP_SELECTARG1=2)
0x415692  SetTextureStageState(0, D3DTSS_COLORARG1=2, D3DTA_TEXTURE=2)
0x415742  SetTextureStageState(0, D3DTSS_ALPHAOP=4,   D3DTOP_MODULATE=4)
0x415770  SetTextureStageState(0, D3DTSS_ALPHAARG1=5, D3DTA_TEXTURE=2)
0x41579a  SetTextureStageState(0, D3DTSS_ALPHAARG2=6, D3DTA_TFACTOR=3)
; stage1
0x4156c0  SetTextureStageState(1, D3DTSS_COLOROP=1,   D3DTOP_SELECTARG1=2)
0x4156e6  SetTextureStageState(1, D3DTSS_COLORARG1=2, D3DTA_TEXTURE=2)
0x4157c4  SetTextureStageState(1, D3DTSS_ALPHAOP=4,   D3DTOP_MODULATE=4)
0x4157f2  SetTextureStageState(1, D3DTSS_ALPHAARG1=5, D3DTA_TEXTURE=2)
0x41581c  SetTextureStageState(1, D3DTSS_ALPHAARG2=6, D3DTA_TFACTOR=3)
0x415846  SetTextureStageState(1, D3DTSS_ALPHAOP=4,   D3DTOP_DISABLE=1)
; stage2 关闭
0x415714  SetTextureStageState(2, D3DTSS_COLOROP=1,   D3DTOP_DISABLE=1)
```

⇒ 输出颜色来自**一个纹理 stage**(SELECTARG1),输出 alpha = 该纹理 alpha
× `TFACTOR.a`(= 层 A),**没有阈值**;`T` 不进入这两个 stage 状态。

`T` 进入的是**顶点色**:`0x415462-0x415532` 连续构造 4 个顶点
(`CALL 0x00417204` ×4 + `0x00417258`),每个顶点的 D3DCOLOR 由
`0x414d09-0x414d21` 的灰度展开(`alpha<<24|<<16|<<8|alpha`)给出,位置/颜色参数
来自 `T`、层矩形与 `0x58ebc0/c8/d0/e8/f0/f8` 常量。

⇒ **官方过渡 = 一块四角 α 渐变的 quad × mask 纹理**,渐变随 `T` 扫过层矩形。
这解释了官方为什么是「平滑的半透明边界」。

## 3. 影响与下一步

- 我们的阈值模型在**任何**随 T 推进的过渡上都会给出硬边(开幕时钟最明显)。
- 要 1:1:把 `plan_transition` 的顶点 alpha 改成**逐角**值(按 `T` 与层矩形
  计算,公式需继续解 `0x415462-0x415532` 的浮点链),mask 仅作像素级乘子
  (`mask_channel × layer_alpha`),不再参与阈值。
- 迁移前不要再用 `transition_coverage` 的斜率调参「看起来柔和一点」——
  那只是把拟合误差换了个方向。

| **64** | 0 / 0 | 0 / 0 | 0 / **0.498** | 0 / 1.000 | **0.875** / 1.000 |

(mask=0 / mask=128)

### 6.1 从表里能直接确认的事实

1. **mask=128 在 T=128 恒为 0.5**(四个 TA 全部)——与 TA 无关;
2. **mask=128 在 T=192 恒为 1.0**;T<=64 恒为 0;
3. **mask=0 在 T<=192 恒为 0**(唯一例外 TA=2/T=192 = 0.502);
4. **mask=0 在 T=255 精确等于 `(256 - TA/2)/256`**:
   TA=2→0.996、64→0.875、128→0.749、192→0.624(误差 ≤0.004)。

### 6.2 为什么还定不了闭式

只有 **2 个 mask 电平**(0 / 0.5),而候选模型需要 3 个自由度(阈值、斜率、饱和):
第 1/2/3 条把「T=128 时 α=mask、T=192 时 α=2·mask(TA>=64)」钉死了,
但第 4 条(TA=2 时 T=192/255 的 0.5/0.996)与任何单调 (阈值,斜率) 组合都冲突 ——
除非 TA 还改变了**取样/几何**(伪代码里过渡是按 `0x130`/`0xb0` 表**分块**画
`DrawPrimitiveUP` 的,顶点 alpha 可能逐块不同,单块 60×60 时退化成单值)。
没有 3 个以上 mask 电平(或带渐变的 mask 图)就无法把「阈值/斜率/分块」分开。

3. 用这两条曲线判定 α(mask,T,TA) 是「阈值+斜率」「lerp」还是「分块顶点 alpha」;
4. 再替换 `transition_coverage`。

## 7. 结论修正:官方不是「逐像素覆盖率公式」,是 **CPU 轮廓带 + 逐块顶点 α**

重新读 `FUN_00414ba4` 的伪代码(REA `ev_128a7aa3…`)后,§2 的「阈值模型」也站不住了:

- stage1 的 `ALPHAOP` 最后被设成 **`D3DTOP_DISABLE`**(`0x415846`),
  即 stage1 整级关闭 ⇒ 最终 `alpha = tex0.a × TFACTOR.a`,
  **mask 根本不参与 alpha**;
- `TFACTOR` 是 `SetRenderState(0x3C, …)` 的**逐次绘制标量**,
  在循环里每画一块就设一次;
- 循环体(`0x414f60-0x415943`)按 `+0x130`(部件)与 `+0xb0`(分块)两张表
  逐块构造 4 个顶点,`DrawPrimitiveUP(D3DPT_TRIANGLESTRIP, 2, .., stride=0x54)`;
  每块的 y 起点 `dStack_88` 与终点 `dStack_b0` 由 `local_e0/local_1a0`(比例)
  和块宽 `[+0xb0+j*4]` 递推,UV 也是逐块算的。

⇒ 官方是**在 CPU 上沿 mask 的等值线切块、给每条带子按 T 算 α、再把带子当
triangle strip 画出来**。这解释了为什么:

- `TA` 越大 = 分块越密 = 带子越窄 = 「くっきり」;
- §6 的表里 60×60 单块单元会给出「整块 0.5 / 突然 1.0 / 255 时 1−TA/512」这种
  **非逐像素函数**能解释的台阶(每格只有一个块,T 决定这块落在带的哪一侧);
- 任何 `α=f(mask,T,TA)` 的逐像素闭式都必然在某个 TA/T 组合上崩掉。

**因此**:要 1:1,不能继续调 `transition_coverage` 的公式,必须实现
「轮廓带构建 + 逐块顶点 alpha」这条渲染路径(soft/wgpu 都要)。
工作量大,但这是官方真实实现;现有逐像素模型保留作为**临时**近似并在
`docs/architecture/backends.md` 账本里标 `open`。

## 8. 补一层:α 是常量,软边来自**几何**(等值线带)

§7 写「逐块顶点 α」,再把 `FUN_00414ba4` 的赋值链对完一遍后需要修正一处:

- 4 个顶点用的颜色都是 `[ESP+0x2e8]` = `alpha<<24|<<16|<<8|alpha`(灰度 A),
  **同一层所有顶点同色**;
- `SetRenderState(D3DRS_TEXTUREFACTOR, …)` 每层设一次,值也只由层 A 决定;
- stage1 `ALPHAOP=DISABLE` ⇒ 最终 `alpha = tex0.a × A`,**与 mask、T 都无关**。

所以过渡的「哪里看得见」完全是**几何**决定的:循环
(`0x414f60-0x415943`,按 `+0x130` 部件表 / `+0xb0` 分块表)把层的可见区域
沿 mask 的**等值线**切成 triangle strip 逐块画出,边界用 16.16 定点在块内插值
(`0x414fa3` 起的 `×65536 → FISTP → 拆整数/小数`),`T` 只决定等值线扫到哪里,
`TA` 决定分块数(精度)。

⇒ 结论定稿:

1. **不存在逐像素覆盖率公式**;任何 `α=f(mask,T,TA)` 都无法解释 §6 的表;
2. 官方软边 = **等值线几何**的平滑(顶点落在 mask 的等值线上),
   不是 alpha 渐变;
3. 要 1:1 必须实现「mask 等值线 → triangle strip(按 `+0xb0`/`+0x130` 表分块)
   + 常量 alpha = A」;这与我们现在的「一个 quad + 覆盖率公式」是两种实现。

## 10. 宽带覆盖率模型:试过并**撤回**(2026-10-27)

有一轮把覆盖率改成「宽带」形式(中心 `c=1-t`、带宽 `w=1/6`,
`α=clamp((m-c)/w+t,0,1)`),在 §6 的 36 点表上 rms 0.0043、逐点 ≤8/255,

- 开幕的菱形格(`cg/tr/ysr023` 一类的平滑梯度掩膜)在窄带阈值下是
  「每像素灰度决定菱形半径」⇒ 逐帧锐利生长的黑菱形,与官方 0.495 的
  开幕参考帧逐像素一致;

## 12. 定稿:覆盖率两档,由 `TA` 分流(2026-10-27 实机验收)

用户口径(逐字):「标题的 logo 浮现是没问题的,是剧情中的过渡便锐利了」,
并点名「演出 1 的最后淡出」。两者是同一条固定管线过渡、同一个覆盖率函数,
差别只在脚本给的 `TA`:

| 场景 | `TA` | 需要的形态 |
|---|---|---|
| 标题 logo 浮现(`SPL401`) | 128 | 硬边(已验收,**必须逐位不变**) |
| 立绘快门(`ysr011/012`) | 128 | 硬边(竖百叶) |
| 演出 1 最后淡出 `\FOUT(1500,5)`(`SPL101`) | 4 | 宽的柔边幕 |

```text
c     = 1 - 2*fade
K     = 30 + 70*fade                 旧式斜率(等效带宽 1/K ≈ 0.02..0.033)
wide  = 0.16 / TA                    剧情柔带宽度(mask 单位;TA=4 → 0.04)

a = wide <= 1/K ?  clamp(K*(m - c))        // 硬档:与旧实现**逐位一致**
                :  clamp((m - c)/wide)     // 软档:从等值线起的宽渐变
```

- **硬档逐位一致**由测试 `transition_coverage_keeps_hard_edge_at_ta_128`
  保证(mask 0..255 × fade 5 点,逐值等于旧式);
- 实机:`TA=128` 的标题帧 22/28/40/52 与改动前**逐像素 0 差异**;
- 实机:`TA=4` 的幕从「硬边」变为 ~40px 柔带,覆盖区内部仍是实黑
  (`ysr005` 的边界灰度梯度 ≈0.001/px,0.04 mask 单位 ≈ 40px);
- 软/硬后端一致性:同一帧 `dark%` 差 ≤2%(4608:0.350 vs 0.372;
  4630:0.586 vs 0.605;4650:0.970 vs 0.983)。

### 12.3 反汇编再确认:官方是「quad 网格 + 每格累计比例」,不是逐像素公式

`FUN_00414ba4` 的主循环(2026-10-27 用 Ghidra 12.1.4 反编译官方 SDK 0.495,
`sha256=4f5eefa3…`):

```c
local_64 = *(byte *)(layer + 0xa6);      // 部件数
bQuads   = *(byte *)(layer + 0xa7);      // 是否走分块网格
...
do {                                     // 外层:部件 table +0x130
  partW = layer[+0x130 + i*4] / 100.0;
  do {                                   // 内层:分块 table +0xb0
    blkH = layer[+0xb0 + j*4] / 100.0;
    // 16.16 定点:ROUND(x*65536) → 取整/取小数
    v0 = ((fixed(accX) * 1.52587890625e-05) / blkH) * 0.25;   // 1/65536
    v1 = ((fixed(accY) * 1.52587890625e-05) / partW) * 0.25;
    build_vertex(..., v0 + 1.0);  build_vertex(..., v0 + 1.0);
    build_vertex(..., v1 + 0.0);  build_vertex(..., v1 + 0.0);
    ... 旋转(度→弧度 0.017453292)...
    DrawPrimitiveUP(D3DPT_TRIANGLESTRIP, 2, verts, 0x54);     // 一格一个 quad
  } while (j < blocks);
} while (i < parts);
```

⇒ **柔带 = 一格宽**:每格顶点带「累计覆盖比例」,格内线性插值,比例项乘 `0.25`。
所以 `TA` 越大格越密、边界越贴近 mask 等值线(「くっきり」),越小格越粗、边界越宽
(演出 1 最后淡出)。我们的 `0.16/TA` 就是「一格 ≈ 0.25/TA 个 mask 单位」的
行为替身;要 1:1 必须落地这张 quad 网格(§7/§8 的 contour 路径),而不是继续
调覆盖率系数。

### 12.4 落地 grid 还缺什么(静态 RE 的边界,2026-10-27)

查过 `FUN_0043772c`(层尺寸写回 `+0x78/+0x7c` 的那条链):它只管
「按 SX/SY 重建层表面」,与 `+0x130/+0xb0` 两张表无关;`yu-format` 里也没有
按这些偏移解析层对象的代码。结论:

| 数据 | 现状 |
|---|---|
| `+0xa6` 部件数 / `+0xa7` 走不走网格 | **未读**:层对象是引擎运行时建的,不由 yssd 记录直接给出 |
| `+0x130` 部件宽度表 / `+0xb0` 分块高度表 | **未读**,契约里这条幕 `parts=[]` |
| 顶点 α 的累加器初值(`dStack_1a8`/`dStack_f8`) | **未定**:决定 T→扫描位置 |
| 旋转(度→弧度 `0.017453292`)、`*0.25` 顶点色 | 已解 |

两条补齐路径:

1. **运行时 dump**:官方跑到这条幕时,按层指针读 `+0x80..+0x140` 一段内存,
   直接拿到两张表和累加器初值(最快,一次即可);
2. **静态续挖**:沿层创建链找谁 `mov [layer+0x130]` / `[layer+0xb0]`
   (Ghidra 上按结构体偏移扫描,不必逐函数反编译)。

拿到后实现 = `plan_transition` 换成「部件 × 分块」网格发射(soft 同步三角形
光栅 + 逐顶点 α 插值),验收门是已写好的 40 格 oracle(`#[ignore]`)。
在此之前 `transition_coverage` 的 `1/K + 0.16/TA²` 是**行为替身**,不是官方机制。

### 12.5 层对象布局(构造函数反编译,2026-10-27)

`FUN_00465730` 是层对象分配器:`malloc(0x640)`,即**层对象 0x640 字节**。
它写死的初值:

```c
layer[+0x80] = 0x100;      // A = 256
layer[+0x82] = 0x100;      // T = 256(默认满)
layer[+0x78] = 1; layer[+0x7c] = 1;     // 尺寸(之后由 SX/SY 写回)
layer[+0x1c0] = 10000; layer[+0x1c8] = 10000;   // % 单位(=100.0)
layer[+0x204] = 0x80; layer[+0x208] = "ieFE.exe";  // effect DLL 名
layer[+0x620..0x628] = 1.0f;                    // 缩放/旋转因子
layer[+0x86] = 0; layer[+0x89] = 1;
layer[+0x4c]/[+0x210]/[+0x218] = malloc(0x105)   // 三个字符串缓冲
```

⇒ **`+0xa6/+0xa7/+0xb0/+0x130` 构造函数不碰**(保持 0),所以网格表是
CG/精灵装载路径后填的。这解释了为什么我们的契约里 `parts=[]`:问题不在
读取偏移,而在「CG 命令 → 层对象」这一段我们还没有对应实现。

⇒ 参见 `FUN_00414ba4` 的守卫 `if (layer[+0xa7]) { … }`:表为空时官方
**不走**网格循环。这为「哪些过渡是 4 顶点 quad、哪些是网格」提供了判据,
也说明先前把「网格」当成所有过渡的通用路径是不对的——需要先判定该层
是否带表。

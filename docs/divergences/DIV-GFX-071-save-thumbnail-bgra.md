# DIV-GFX-071 · 官方存档缩略图(DNO3 图像块 B 段)是 BGRA8,读档界面整图红蓝互换

- 状态: fixed(2026-10-31)
- 优先级: 高(读档界面主视觉直接错色)
- 发现日期 / 发现方式: 2026-10-31,主人实机目检(`<game-b>` 读档界面,
  官方存的槽缩略图整体偏蓝;本内核自存自读的槽正常)。

## 复现

- 游戏位置 / 操作序列: `<game-b>` v494,`save/` 下官方 exe 写出的
  save00001–5(.sd 容器 DNO3 = btype1 图像块),用本内核读档界面
  (`es_SaveLoad.yst` 的 `LOAD[FILE DNO=3 ID=_TMP_OF]` 链)显示缩略图。
- 锚点: sid 19 pc984(`LOAD[FILE DNO=3]`);图像块格式无手册页。

## 官方行为(真值层级 3:官方存档字节自证)

DNO3 块解压后 B 段(30000B = 100×75×4)的像素序是 **BGRA8**:

- save00001(校园场景)顶部 1/3 均值 `[B=240.6, G=197.1, R=114.7]`
  —— 按 BGRA 解释是淡蓝天空 + 绿草,按 RGBA 解释是橙天(错误);
- save00003(暖色卧室)整图 7416/7444 像素 ch2>R,按 BGRA 解释是
  暖色调,按 RGBA 解释整图偏蓝(主人截图所见);
- save00004(選択肢黑屏)中部 600 像素 ch0>ch2 —— 按 BGRA 是本作
  蓝色系选择框,按 RGBA 解释成橙色;
- 五个官方存档按 BGRA 解释全部得到自然色(肤色/蓝天/暖室内),
  按 RGBA 解释全部错色。双解释 PNG 逐张目检定案。

**alpha 通道**:官方 B 段 alpha 行 0/37/74 = 255、其余恒 254(与场景无关
——全黑選択肢截图与校园场景模式完全相同),是官方采集管线的痕迹;
机理未反,不猜。旁证:官方引擎内存表面本就是 BGRA
(`DIV-GFX-063` 滤镜矩阵 `117B+601G+306R` 按 B/G/R 内存序)。

## 内核行为

`yu-save::image_block` 把 B 段按 RGBA8 直通(`decode` 原样、`encode` 原样),
内部 RGBA 读成磁盘序 ⇒ R/B 互换。此前取证样本(0.495 SDK save00001)
是纯黑屏,黑像素 R/B 互换后不变,通道序从未被钉过
(`PROGRESS.md` 成果 THUMB-BGRA 之前的记录只钉了形状)。

## 修法

`image_block::swap_rb`(自逆)加在 encode/decode 两端各一次:
磁盘 B 段 = BGRA8,内部 `CapturedImage` 恒 RGBA8。自存自读对称互换后
行为不变;官方存档解码恢复正常色;本内核写盘的 B 段从此与官方同序
(官方引擎读本内核存档缩略图也正确)。

## 回归

- 新增单测 `image_block::tests::disk_pixel_order_is_official_bgra`
  (钉磁盘字节序,黑样本钉不住的东西这次钉死);
- `decode_accepts_0479_descriptor_layout` 的手工 B 段改为按官方序构造;
- 端到端(生产路径 `SaveState::load_image` + PNG 落图目检,探针用后即删):
  `<game-b>` save00002/00004/00005 均恢复自然色,選択肢框回到本作蓝色系。

## 残余

- **写盘 alpha 与官方差 1**(字节级):官方 254(行 0/37/74 为 255),
  本内核按采集真值写 255。渲染上 254/255 ≈ 0.4% 混合差,不可见;
  机理未反之前不照抄魔数,保持本行为并在此留档。
- 修法落地前由本内核写出的存档(save00011/save10001 等)B 段是 RGBA,
  修复后读取会互换显色 —— 属开发期产物,重新存档即覆盖,不做兼容猜测。

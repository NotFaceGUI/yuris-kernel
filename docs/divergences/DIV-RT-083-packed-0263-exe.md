# DIV-RT-083 · 0.263 官方 exe 带壳,图像描述符常量未独立核对

> 状态:**open(残余)**。仅影响 0.263(`0x107` 旧式记录容器)写出的缩略图
> 块;变量块与容器结构不受影响。

## 事实

- `<0.263 商业>` 的官方 exe `.text` 只有约 32KB,其余为高熵 overlay
  (熵约 8.0),静态反编译拿不到图像块的装载/校验常量。
- 内核现用 `LAYOUT_0292`(`A=0x2B0`,w/h 在 `+0x258/+0x25C`)：
  - 直接证据来自官方 0.292 SDK `yu-ris.exe` 的 LOAD 图像分支
    `FUN_00430400`:对解压载荷硬校验 `payload[0] == 0x2B0`,随后把 A 段
    的 `+0x258/+0x25C` 当 w/h;
  - 旁证:0.290 商业存档 DNO=3 的 `A=0x7E0`,w/h 同样在 A 段
    `+0x258/+0x25C`,说明旧代描述符的 w/h 偏移稳定、A 长度随构建变化。
- 0.263 官方 `gsd/kidoku/seld.sd` 三份系统存档自证的是**容器布局**
  (旧式记录表、无压缩、`+0x0C=0`),不含图像块,所以不能反推 A 常量。

## 风险

若 0.263 官方 LOAD 校验的 A 长度不是 `0x2B0`,内核写出的缩略图块会被
官方拒收(变量块仍可读)。当前没有 0.263 官方**玩家存档**样本可对照。

## 下一步

1. 取一份 0.263 官方玩家存档(含 btype 1 缩略图块),按 `detect_layout`
   反推 A 与 w/h 偏移后修正 `LAYOUT_0292` 或新增旧代布局;
2. 或脱壳/内存 dump 0.263 exe,定位图像块 LOAD 分支的常量比较;
3. 两条都拿不到时维持现状,并在 0.263 写盘时保留现有诊断。

关联:`crates/yu-save/src/image_block.rs`(`LAYOUT_0292` 注释)、
`crates/yu-save/src/profile.rs`(`0x0107` 行)、DIV-RT-084。

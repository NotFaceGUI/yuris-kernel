# DIV-013 · V2 变量前缀 0x23 = `$@`(数值变量转字符串),不是旧式字符串空间

- 状态: **fixed**(2026-11-17;按脚本版本分支)
- 优先级: 高(2xx 表达式求值)
- 发现日期 / 发现方式: 2026-11-17;两套官方语料变量引用前缀 +
  `shimamura-sakura/yuris_decompiler`(MIT)的 `InsTyqV200/V300` 事实对照。

## 事实

- V5 / V300+:`0x23` = `&$`(旧式字符串空间),`0x60` = `&@`(旧式数值空间);
  本仓库既有证据(DIV-RT-017):`$G/$L` 编译为前缀 0x23、`@G/@L` 为 0x60。
- V2(200 < v < 300):`0x23` = **`$@`**(把数值变量按字符串读取),
  `0x60` 不是 V2 的 tyq。两套语料的 0x23 变量 id 绝大多数在 `ysv.ybn`
  声明为 INT / FLT(0.292 id 1162、1164、1739… 全是 ty=1),
  与"字符串空间"的读法矛盾。
- 本仓库语料的表达式记录流里没有独立的 0x23/0x60 opcode(只有变量引用
  载荷首字节出现),故版本分支放在**读取路径**而非表达式解码器。

## 实现

- `VarSpace::from_prefix` 保持不变(0x23 → `LegacyStr`),避免影响 V5;
- `VmAccess::read`:当前脚本 `200 < version < 300` 且原始前缀为 0x23 时,
  先按声明类型归一化读取,再把结果 `to_event_repr()` 转成字符串返回;
- `read_scalar_int` 对同一条件返回 `None`,强制回退到 `read`(不能把
  `$@` 当整数快路径)。

## 验证

- 0.292 / 0.255 标题/按钮流程(使用 `$@` 的 `$@PERCENT` 等)无类型错误;
- 现有 `cargo test -p yu-rt` 全绿(109 单测 + 125 fixture);
- 语料普查:0.292 15 个、0.255 13 个 0x23 引用,全部走分支读取。

# DIV-RT-017 · 系统变量 ABI 表来源与选表规则

- 状态: **已收口**(2026-11-07)
- 影响面: `yu-rt`(`sysvar_abi`)、启动路径、`crates/yu-rt/data/`
- 关联: DIV-RT-016(ysv 指纹校验的建立),本档案扩展其选表覆盖面

## 1. 问题

商业发行版不带编译器(`data.ypf` 内 `ycd` 命中数 0),系统变量 `id → 名字/类型/维数`
只能靠内嵌 ABI 表。原实现只内嵌 4 张表(0292/0466/0479/0495),任何其他构建
(实测 v486)都会因"整表必须逐项相等"而 `table.version` Fatal 拒绝启动。

## 2. 事实

- `ysv.ybn` 记录只有 `kind/flag/file_id/slot/ty/dims` + 初值,**没有名字**;
  名字在编译期由 `YSCom.ycd` 决定,产物里不保留。
- 同一 id 在不同版本语义不同(实测 id 50:0.292 `_SYSTEM_PATH`、
  0.466/0.479 `_PINT[11]`、0.495 `_INT[1]`)。
- 官方引擎按 `switch(id)` 分派,`default` 分支 = 普通槽位,不读任何表文件。
- `YU-RIS_Guide` 归档 81 个官方 SDK,提取出 **27 个唯一 `YSCom.ycd`**;
  `0.481 (0.02)` 与 `0.486 (0.06)` 的 ycd **sha 完全相同**(`f7380aba`),
  且覆盖 0.481–0.493 共 13 个版本(36 个归档)。

## 3. 决策

1. 表来源全部改为官方 ycd 转写,表头记录 `source_ycd_sha256` 与 `# covers` 区间;
   同一 sha 只保留一份。
2. 校验规则从"整表逐项相等"改为**前缀逐项相等**:
   `var_id < 表长` 的 `kind=1` 镜像必须全部存在且 `(type, dims)` 一致;
   `var_id >= 表长` 的追加项忽略(官方 `default` 行为)。
3. 兜底降级只允许 **`wrong == 0`**(没有类型/维数不符)且缺项 ≤2 且唯一最接近;
   只要有类型不符,该表即判为错版本,绝不降级采用。
4. 多张表内容相同时(0494/0495),按游戏 `ysv` 自报版本号挑最贴切的一张,
   仅影响日志显示,不影响语义。

## 4. 验证

| 样本 | ysv 版本 | 选中表 | 结果 |
|---|---|---|---|
| `project-eris` | 495 | `sysvar-abi-0495-a626e40a.tsv` | 启动正常 |
| `<game-b>` | 494 | `sysvar-abi-0494-185f14aa.tsv` | 启动正常 |
| `<game-481>` | 481 | `sysvar-abi-0495-a626e40a.tsv` | 启动正常 |
| `<game-d>` | 486 | `sysvar-abi-0481-0493-f7380aba.tsv` | **修复前 Fatal,现启动正常** |

v486 实测前缀 541/541 完全吻合,尾部追加 644 项按普通槽位处理。

## 5. 遗留

- 表外追加项无名字:不影响已有 id 语义,但新追加的系统变量若为计算型,
  会退化为普通槽位(读 0)。启动日志会显示 `covers=` 区间,便于定位。
- `case-tables-0495.tsv`、`button-code-abi.tsv` 仍只有 0.495 一份证据;
  若 5xx 改变了转换表/按钮码,需另做取证。

## 6. 生成工具

`crates/yu-rt/examples/gen_abi_tsv.rs`(ycd → TSV)与
`crates/yu-rt/examples/abi_match.rs`(TSV × ysv 逐项差异)均为只读探针,
可对新增 SDK 重跑。

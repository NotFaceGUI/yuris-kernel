# DIV-RT-017 · 系统变量 ABI 表来源与选表规则

- 状态: **已收口**(2026-11-07)
- 影响面: `yu-rt`(`sysvar_abi`)、启动路径、`crates/yu-rt/data/`
- 关联: DIV-RT-016(ysv 指纹校验的建立),本档案扩展其选表覆盖面

## 1. 问题

商业发行版不带编译器(`data.ypf` 内 `ycd` 命中数 0),系统变量 `id → 名字/类型/维数`
只能靠内嵌 ABI 表。原实现只内嵌 4 张表(0292/0466/0479/0495),任何其他构建
(实测 v486)都会因"整表必须逐项相等"而 `table.version` Fatal 拒绝启动。

## 2. 事实

- `ysv.ybn` 记录只有 `kind/flag/file_id/slot/ty/dims` + 初值,**没有名字**;
  名字在编译期由 `YSCom.ycd` 决定,产物里不保留。
- 同一 id 在不同版本语义不同(实测 id 50:0.292 `_SYSTEM_PATH`、
  0.466/0.479 `_PINT[11]`、0.495 `_INT[1]`)。
- 官方引擎按 `switch(id)` 分派,`default` 分支 = 普通槽位,不读任何表文件。
- `YU-RIS_Guide` 归档 81 个官方 SDK,提取出 **27 个唯一 `YSCom.ycd`**;
  `0.481 (0.02)` 与 `0.486 (0.06)` 的 ycd **sha 完全相同**(`f7380aba`),
  且覆盖 0.481–0.493 共 13 个版本(36 个归档)。

## 3. 决策

1. 表来源全部改为官方 ycd 转写,表头记录 `source_ycd_sha256` 与 `# covers` 区间;
   同一 sha 只保留一份。
2. 校验规则从"整表逐项相等"改为**前缀逐项相等**:
   `var_id < 表长` 的 `kind=1` 镜像必须全部存在且 `(type, dims)` 一致;
   `var_id >= 表长` 的追加项忽略(官方 `default` 行为)。
3. 兜底降级只允许 **`wrong == 0`**(没有类型/维数不符)且缺项 ≤2 且唯一最接近;
   只要有类型不符,该表即判为错版本,绝不降级采用。
4. 多张表内容相同时(0494/0495),按游戏 `ysv` 自报版本号挑最贴切的一张,
   仅影响日志显示,不影响语义。

## 4. 验证

| 样本 | ysv 版本 | 选中表 | 结果 |
|---|---|---|---|
| `project-eris` | 495 | `sysvar-abi-0495-a626e40a.tsv` | 启动正常 |
| `<game-b>` | 494 | `sysvar-abi-0494-185f14aa.tsv` | 启动正常 |
| `<game-481>` | 481 | `sysvar-abi-0495-a626e40a.tsv` | 启动正常 |
| `<game-d>` | 486 | `sysvar-abi-0481-0493-f7380aba.tsv` | **修复前 Fatal,现启动正常** |

v486 实测前缀 541/541 完全吻合,尾部追加 644 项按普通槽位处理。

## 5. 遗留

- 表外追加项无名字:不影响已有 id 语义,但新追加的系统变量若为计算型,
  会退化为普通槽位(读 0)。启动日志会显示 `covers=` 区间,便于定位。
- `case-tables-0495.tsv`、`button-code-abi.tsv` 仍只有 0.495 一份证据;
  若 5xx 改变了转换表/按钮码,需另做取证。

## 6. 生成工具

`crates/yu-rt/examples/gen_abi_tsv.rs`(ycd → TSV)与
`crates/yu-rt/examples/abi_match.rs`(TSV × ysv 逐项差异)均为只读探针,
可对新增 SDK 重跑。

## 7. 2xx 商业构建:结构派生,不另建 per-build 表(2026-11-28)

### 7.1 SDK 现状

`YU-RIS_Guide` 归档里 2xx 只有:

- Beta 2:`0.255 (0.55).exe`(官方 ycd 已转写为 `sysvar-abi-0255-81a05c0c.tsv`);
- Beta 3:`0.276 - Sample.lzh`(**只有源码 sample,不含 `YSCom.ycd`**)与
  `0.292 (0.92).exe`(ycd 已转写为 `sysvar-abi-0292-e7016b1e.tsv`)。

没有 0.263/0.290 的官方 `YSCom.ycd`。因此不能用"再加两张表"的方式支持
这两类商业构建,否则每遇到一个商业 fork 就要新增一张表。

### 7.2 实测差异

| 样本 | ysv 版本 | 系统变量前缀 | 与官方族的差异 |
|---|---:|---:|---|
| `<0.263 商业>` | 263 | 475 项(id 0..474) | 对 0.255:删 32 个 `_PAD_BUTTON1..32`、32 个 `_PADNUM_BUTTON1..32`;`_DROPFILE` dims `[]→[1024]`;其余逐项一致 |
| `<0.289 商业>` | 289 | 482 项 | 与 0.292 **482/482 全等** |
| `<0.290 商业>` | 290 | 477 项(id 0..476) | 对 0.292:在 id 52 前插入 1 个普通字符串槽,后续整体 +1;尾部少 `_KEYLAST`/`_MOUSELAST`/`_KEYNUM_BACKSLASH`/`_KEYNUM_ANY`/`_CODE_SLASH`/`_CODE_BACKSLASH`;其余逐项一致 |

0.290 的差异不是解析误差:官方 0.290 `merichri.exe`(sha256
`27559ae4…`)的系统变量分派器 `FUN_00410eec` 用一张 **477 项**跳转表
(VA `0x4a3700`),`id 53` 的 case 返回 `0x122`(=290),`id 52` 走 default
(普通槽位)。这与工程 ysv 的 477 项前缀逐项吻合。

### 7.3 派生算法(`SysVarTable::select_for` 第 2 级)

1. **工程前缀**:取 `kind=1` 且 id 从 0 连续、`ty != 0` 的记录;第一个
   `ty == 0` 是用户全局变量区起点,不参与 ABI 对齐。限制:若某个系统变量
   本身声明为 `ty=0`(仅声明无初值),它会被当成用户区起点而失去名字
   (退化为普通槽);官方 SDK 的精确表路径不受影响。
2. **对齐**:对每个官方族做 Needleman-Wunsch:
   - 精确 `(type,dims)` 匹配代价 0;
   - 同 type、dims 变化(如 `_DROPFILE`)代价 1;
   - 跨 type 同槽代价 5(高于"插入 2 + 固定前缀多一个删除 2"),让
     "新槽插入 + 后续后移"优先,而不是把类型变化硬塞到旧槽;
   - 插入/删除代价 2;同代价时优先总位移 `Σ|i-j|` 最小;
   - 基线只取 `seq.len()+64` 的前缀,避免未声明的尾部被当成删除;
   - 锚定 id 0:不允许跳过基线开头(防止整段前缀平移到后面的同型槽)。
3. **选族**:先试前缀全等(官方 SDK 快速路径);否则按
   `(版本距离, 主代价, 位移代价)` 取唯一最优。版本距离来自各族
   `# covers` 区间(区间内 0,区间外取最近端点),只是**提示**,不是
   版本号硬编码;同分即失败闭合(A5)。
4. **名字**:对齐到的槽位继承官方族名字;新增槽位 `_SYSVAR_<id>`;
   type/dims 一律取工程 ysv(观测值)。派生表再跑一次自身校验,失败即拒绝。
5. **来源**:表头/日志记录 `source_ysv_sha256`、基线族名、匹配/改型/插删
   统计;不再落盘 per-build TSV。

### 7.4 验证

| 样本 | 选中基线 | 对齐统计 | 结果 |
|---|---|---|---:|
| `<0.263 商业>` | 0.255 | matches=474 subs=1 inserts=0 deletes=64 | 启动到首帧,`UNIMP=0` |
| `<0.289 商业>` | 0.292(全等) | 482/482 | 启动到首帧 |
| `<0.290 商业>` | 0.292 | matches=476 subs=0 inserts=1 deletes=6 | 启动到首帧,`UNIMP=0` |

单测覆盖三种形态:跨 type 插入(0.290)、32+32 块删除(0.263)、
同槽 dims 变化(`_DROPFILE`);另保留"10 项以上改型必须拒绝"的负例。

# DIV-016 · YPF `<265 无哈希` 假设被官方 0.255 样本否定

- 状态: **fixed(勘误)**;实现不新增"无哈希"族
- 优先级: 中(旧包读取)
- 发现日期 / 发现方式: 2026-11-17,官方 0.255 样本包
  `example-files/v255.ypf` 全量解析。

## 事实

既有低版本计划(来自二手版本轴)称 YPF `<265` 的名字/负载哈希"无";
但官方 0.255 样本逐条实测:

- 版本 255,条目 103,`+0x0C = 0x1063`(索引块字节数,相对语义),
  首负载偏移 `0x20 + 0x1063 = 0x1083`;
- 名字 XOR key `0xFF`,长度表命中 `V000`/`V004` 族(`0x13↔0x0D` 交换);
- **103/103 条名字哈希 = Adler32(解码后名字)**;
- **103/103 条负载校验 = Adler32(解压后负载)**;
- 全部 103 条 `isCompressed=1`(zlib)。

因此"无哈希族"不是该样本的形态;本仓库 `candidate_profiles()` 现有的
`Meta18 + Adler32 名字 + Adler32 负载` 族 + `V000/V004` 长度表 +
`RelativeSize` 已经完整接受该包,不需要放宽校验。

## 决策

- **不**新增 `<265` 无哈希族:没有官方 oracle,放宽会接受结构闭合的
  垃圾索引,违反"多候选/无证据不猜"。
- 计划里的该条按勘误处理;以官方 0.255 产物为准。

## 验证

- `crates/yu-vfs/tests/real_sample.rs::v255_pack_walks_and_closes`
  (`YURIS_SAMPLE_V2_YPF` + `YURIS_SAMPLE_V2_255`):
  103 条闭合、103/103 名字哈希命中、key=0xFF、名字/负载算法均 Adler32、
  `ysc.ybn` 与 `yscfg.ybn` 与参考解包逐字节一致;
- 0.495 / v473 既有样本回归不变(`cargo test -p yu-vfs` 全绿)。

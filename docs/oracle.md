# 对拍方法论(oracle)

本仓库一切实装由对拍驱动: 先有官方行为的机器可比对形式,再有实现。
实现先后顺序服从 oracle 建设顺序。

## 真值优先级

1. **官方 trace** —— 官方引擎在受控输入下的可观测行为记录
2. **SDK 逆向事实** —— 官方二进制反汇编/官方脚本源码结论(旁线笔记,注明出处)
3. **数据自证** —— 官方产物回写一致(如官方 `save/*.sd` 解析后重序列化字节一致)
4. 旧接手线 golden —— 仅回归参考,不作为对齐依据

## L1 · 官方 trace 采集

- 驱动方式: 64 位 Python 控制 32 位官方引擎进程(WOW64 上下文),方法论参考
  旧接手线 `scripts/engine_trace.py`(思路复现,代码重写,不搬运)。
- 采集粒度: 帧序号锚定 + 子系统(vm / graph / sound / input / save)+ 可观测载荷。
- trace 语料**不入库**(体积与隐私),入库的只有采集脚本与期望值摘要。

## trace JSONL 草案

```json
{"frame": 42, "sub": "vm", "kind": "command", "payload": {"name": "CG", "slots": {"FILE": "..."}}}
```

- `frame`: 官方引擎帧锚点;`sub`: 子系统;载荷只记可观测值,不记内部猜测。
- 同一 schema 同时用于官方采集与内核输出 —— diff 才有意义。

## diff 工作流

```text
官方采集(同游戏数据+同输入时间线)
  → 内核回放同数据
  → 逐子系统 diff(yu-trace)
  → 命中分歧 → docs/divergences/DIV-NNN 建档(留痕)
  → 修复 → 该用例 golden 化 → 进回归
```

分层定位(哪一层出的错,由契约边界回答):

| 差异层次 | 判据 | 定位 |
|---|---|---|
| 译码错 | 同一 YSTB 输入的组表/窗口不一致 | yu-format / yu-script |
| 执行错 | 译码一致但命令后状态不一致 | yu-vm / yu-macro |
| 呈现错 | 事件一致但帧层状态不一致 | yu-graphics 等域状态机 |
| 编排错 | 单帧一致但帧间次序不一致 | yu-player |

## 完成定义

一个子系统的"对齐 1:1" = 在全部可用语料上,该子系统的边界输出与官方 trace
零差异,且用例已 golden 化进回归。在此之前一律标注未对齐。

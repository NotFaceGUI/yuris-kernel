# 性能优化待办 · 非 soft 专项（2026-11-11）

> 来源：2026-11-11 只读性能普查（各 crate 热路径审阅 + 仓库既有实测口径）。
> 范围：**不含 `crates/yu-render/soft` 的像素/合成专项**；`yu-render/core` 的共享
> 纹理缓存与文本合成器、`yu-render/wgpu` 仍列入。soft 专项另立文档，不与本表混排。
>
> 口径与约束：
> - 所有项必须保持**像素/字节输出逐位不变**、诊断文案与聚合计数不变、绘制与事件顺序不变；
> - 不得把参与输出迭代的 `BTreeMap` 换成 `HashMap`（`text_draws`、`diags`、`windows`、
>   `screen_snapshots`、声音混音层迭代）；
> - 声音层混音顺序不可改（浮点求和顺序影响波形）；
> - 每项开工前先用 `--frame-stats` 或 `bench` 取一次基线，收工后同口径复测，避免归因错误。
>
> 状态定义：`待办` = 确定性、可直接开工；`已收口` = 已完成并回归（改状态时同时在
> 文末清单记行，避免重复劳动）；`暂缓复审` = 本轮不做，保留编号与内容，待后续单独审。
> 执行任务书：`docs/tasks/task-perf-2026-11-11.md`（T0–T14 批次、依赖、步骤与验收）。
> 编号是稳定 ID，不因暂缓/完成而重排。
>
> 风险定义：`低` = 局部机械改动，现有用例可逐字节对拍；`中` = 涉及公开类型、借用重排
> 或缓存失效，需要全量 golden/像素对拍；`高` = 语义敏感（快照保活、日志裁剪、像素复用），
> 需专项取证与回归。

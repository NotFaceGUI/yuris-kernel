# 任务 04 · LayerEpoch 第一阶段重构（触发式，不立即执行）

- 状态：**触发式（deferred-by-trigger）**，默认不启动
- 优先级：P1（仅当触发条件满足）
- 关联：`DIV-GFX-090`、`DIV-GFX-053`、`DIV-GFX-072`、`DIV-GFX-086`
- 原则：**不是当前任务的待办**。只有同类问题再次出现时才启动；不要为了
  架构整洁提前改。

## 触发条件（任一满足）

1. 再次出现“命令时刻 vs 回放时刻”导致的可见错误，例如：
   - CG/缩略图 hover 显示上一张图；
   - 同 tick `CGEND` 后画面白/黑/旧图；
   - 旧 override/快照被新同名层读到；
   - 存档缩略图、转场、配置界面出现同类时序问题。
2. 为修一个同类边界，需要在 gfx/soft/wgpu 再加第三张 provenance 表，
   或再加一个 `target_live`/`target_base` 特判。
3. 回归测试开始大量依赖“层名 + 执行顺序”而不是显式实例身份。

**未满足以上条件时：不要启动本任务，不要重写回放机制。**

## 背景（为什么触发器存在）

官方 `CGACT` 在命令处理体内立即写目标表面；内核延迟到帧末回放。
当前 `DIV-GFX-090` 用手工冻结的 `ImageTargetBase` + `override_bases` /
`Contents::bases` 对齐了已取证的 CG 预览与 hover 路径。它不是 epoch 模型，
所以每新增一个生命周期边界，都要人工回答：

- 活层还是已删除目标？
- 目标基面/尺寸/fill 是命令时刻的哪一份？
- 同名复用后，这份中间结果属于哪个图层实例？
- 后续 COPY/MERGE 还能不能读它？

漏一项就会再出一个同类 bug。

## 第一阶段目标（只做这个，不做全即时写表面）

**LayerEpoch + 命令时刻输入**，不改掉回放，只把生命周期身份显式化：

1. 图层实例 `(LayerId, epoch)`；`CG` 新建、`CG[FILE]` 换图、`SWAP`、
   `CGEND` 递增/墓碑化。
2. `ImageOp`/`CopyOp` 记录源/目标的 `(id, epoch)` 与命令时刻基面
   （纹理 + fill + 显式尺寸）。
3. 后端表面/缓存键改为 `(id, epoch)`；`CGEND` 只标 dead，消费者结束后
   回收旧 epoch。
4. 用 epoch 替换 `target_base`/`override_bases`/`Contents::bases` 的
   启发式判断；保留冻结输入作为 epoch 快照的一部分。
5. 分三步落地：
   - 1a 加字段与断言，行为不变；
   - 1b 后端键迁移，旧路径兜底；
   - 1c 删除启发式，补复用/删除/快照回归。

## 明确不做

- 不把 VM 改成命令到达即同步写 GPU；
- 不删除每帧回放日志；
- 不改脚本/存档/JSON/音频/输入；
- 不和当前图形修复混在同一次提交。

## 启动时必做

1. 先读 `DIV-GFX-090` 与本任务书，确认触发条件；
2. 复现失败链并记录 trace（脚本 pc、层名、命令序、实际/期望像素）；
3. 先写设计文档（数据结构、生命周期、回收上限、测试矩阵），主人确认后
   再改代码；
4. 不要用“再加一个 if/map”作为临时修复绕过本任务。

## 验收

- 同类 bug 的失败链在 epoch 模型下不再需要特判；
- 旧 epoch 表面有明确回收策略与内存上限；
- gfx/soft/wgpu 全量回归 + 实机 CG 鉴赏/hover/存档缩略图；
- 台账更新：`DIV-GFX-090` 标注 superseded-by-refactor 或保留其历史证据。

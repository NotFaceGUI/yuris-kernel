# v555 独立商业分支支持 · 任务书

> 本文件是 v555 工作的唯一任务口径。启动新会话时，连同
> `v555-startup-prompt.md` 一起交给执行者；两者与 `AGENTS.md` 冲突时，
> 以 `AGENTS.md` 的真值纪律和主人当轮指令为准。

## 1. 任务定位

实现 **v555（YU-RIS 0.555）独立商业分支** 的运行支持，目标是行为与官方
555 引擎 1:1 对齐。

三条不能混淆的边界：

1. **555 不是 495 的延续。** 495 手册/SDK 只能作对照，不能作为 555 语义
   的依据；555 没有手册。
2. **555 也不是“某一版加功能”。** 555 的各个商业构建本身分语义族
   （A-2.1MB / B-PC / C-1），处理体大小与 COM 集合不同；不得用
   `version >= 555` 或单一“555 形态”覆盖全部构建。
3. **本任务是加法，不是改造旧版。** 现有 0.479 / 0.481 / 0.486 / 0.494 /
   0.495 等版本的行为、默认值、金标和诊断必须保持不变。任何共享代码
   改动都不得改变 `version != 555` 的路径。

**最高优先级：不破坏旧版。** 555 的实现可以新增分支、新增表、新增测试，
但不能把 495 的默认改成 555 的默认，也不能让旧版走进 555 专用分支。

## 2. 铁律（按优先级）

1. **真值层级**：官方 555 引擎可观测行为（trace） > 555 官方二进制逆向
   事实 > 555 游戏数据自证 > 旧线 golden（只作回归参考）。无证据 →
   显式 `Unimplemented`/过渡态，禁止猜。
2. **每条 555 结论必须锚定**「构建哈希 + VA/函数 + 语料计数/调用点」。
   代码注释写证据锚点；台账写来源。
3. **精确版本门控**：只对 `version == 555` 生效。禁止 `>= 555`、
   禁止把 556/600 当成 555、禁止把 555 的字段/清单写进旧版默认表。
4. **共享代码改动三条件**：
   - 行为差异由数据/证据驱动（表、profile、命令名、明确参数），不是
     按版本号大段 if；
   - `version != 555` 的默认路径逐字节不变；
   - 同时有 555 回归和至少一个旧版回归（0.495/0.479 corpus 或 fixture）。
5. **禁止宿主特化绕过**：启动 logo/CAUTION/转场必须由剧本/引擎数据驱动；
   不允许在桌面宿主里硬编码画面、顺序或计时来“看起来像官方”。
6. **不使用 495 手册补 555 的洞**；手册缺页但 555 证据足够时可以实现，
   台账标 `fixed(no-manual)`；官方空桩标 `aligned-stub`；官方不支持标
   `unsupported-by-official`。`Unimplemented` 只能过渡，不能终态。
7. **不修改游戏脚本/数据**；不复制旧线代码（事实可引用并注明出处）。
8. **E-mote 维持 `deferred(master)`**；不纳入本任务。
9. **未经主人明确指令不执行任何 git 写操作**（含提交、推送、切分支、
   reset、stash）。

## 3. 非破坏矩阵（每轮必须过）

| 范围 | 必须保持 | 验证 |
|---|---|---|
| 版本门控 | 555 精确；556/600 不继承 | `semantics` 单测 + 旧版 fixture |
| 命令分派 | 旧版默认槽/空桩清单不变 | `yu-rt` fixture/golden |
| 系统变量 | 旧版 ABI 与缺失语义不变 | `sysvar` 单测 + corpus |
| 文本/TEXT | 旧版行切分/推进不变 | `fixture::text` |
| PRODUCT | 旧版 COM 行为不变 | `fixture::product` |
| 图形查询 | 旧版 CGINFO 字段语义不变 | `yu-gfx/tests/info_query` |
| 存档 | 旧版容器布局不变 | `yu-save` 测试 |
| 语料 | 旧版工程可启动、可到标题 | headless 回归命令 |

**禁止用“全量测试太重”跳过旧版回归。** 至少跑受影响 crate 的 lib +
fixture；跨域改动追加 corpus/golden。

## 5. 工作流（每项改动）

1. **取证**：555 exe 反编译/汇编、555 语料、官方 trace 三者至少两条；
   记录构建哈希 + VA/函数 + 调用点。
2. **落账**：先写 `docs/formats/v555-truth-2026-11-21.md` 或 divergence，
   写清现状、证据、影响面。
3. **实现**：优先数据驱动/表驱动；共享路径改动加 exact-555 gate；
   旧版路径保持原默认。
4. **测试**：
   - 555：新增 fixture，锚定命令/参数/事件；
   - 旧版：至少一个既有 fixture/golden 回归；
   - 图形：`yu-gfx/tests/info_query` 或显示 JSON 断言。
5. **运行**：headless 到标题，桌面截图；记录原始输出。
6. **收口**：`PROGRESS.md` 追加成果（命令 + 原始结果）；更新台账/
   coverage/provenance；不提交 git。

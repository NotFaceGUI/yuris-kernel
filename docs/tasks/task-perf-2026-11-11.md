## 0. 任务粒度与状态口径

- **台账条目**（#N）= 最小可勾销单位；一个条目可以是一条命令、一次缓存或一个类型替换。
- **批次**（TN）= 一条可独立回归的提交序列；一个批次只动一个子系统或一个明确主题。
- **状态**：`未开始` → `进行中` → `已完成`；`暂停` 仅用于被语义取证阻塞。
- **完成回写**：
  1. 台账对应行状态改为 `已收口`，并在文末“已收口”清单记一行（日期 + 提交号）；
  2. 本任务书批次状态改为 `已完成（日期 / 提交号）`；
  3. `PROGRESS.md` 追加“成果 N”，附验证命令与原始结果；
  4. 若过程中发现新问题，**新增台账行**，不静默扩大本批范围。

### T1 · gfx 帧投影与字段克隆（#1、#19、#83）

**目标**：去掉每帧一次无用的整帧深拷贝，并消除帧字段的重复克隆/排序临时缓冲。

**步骤**
1. #1：先确认 `frame()` 的重复调用者只有 `capture.rs` 的低频回放；删除
   `state.rs:1318` 的 `f.clone()` 缓存填充。若担心重复调用，改缓存
   `Rc<CompositorFrame>` + `frame_shared()`，`frame()` 保留 owned 返回。
2. #19：`image_probe_order` 用 `clone_from` 复用容量；`screen_snapshots`
   先保持 `BTreeMap<CopyId, Arc<...>>`，评估是否改 `Arc<BTreeMap>` 共享；
   `windows`/`diagnostics` 仅在内容变化时重建（可先加代次/脏标记）。
3. #83：`f.layers.sort_by`、快照层 `sort_by`、`keyed.sort()` 在键唯一
   （`seq` 全局唯一）时改 `sort_unstable_by`/`sort_unstable`。

**护栏**
- `frame()` 连续调用必须逐字节相同；`last_screen_key` 的计算输入不变。
- `f.layers`/`f.windows`/`f.diagnostics` 的输出顺序不变。
- 不改 `screen_contract_key` 的哈希算法。

**验收**
- `cargo test -p yu-gfx` 全绿；`frame_cost` 结构护栏全绿。
- 菜单重帧 `work`/`render` p95 下降；稳态不回退。
- golden JSON 对比无差异。

**收益**：每帧 0.3–1.5ms；菜单 1400 层与 T2 合计 3–8ms。

**目标**：文本内容不变时不再每帧重排版/深拷贝。

**步骤**

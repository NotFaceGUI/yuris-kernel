> 用户目标:让 ERIS demo 正常游玩。本文件 = 本轮审查的**事实源**;
> 真值层级见 `AGENTS.md` §0。语料 `<project-eris>`(data.ypf,官方 0.495 全量编译)。
> 会话宿主:`yu-desktop` release(wgpu,1200x900,viewport 800x600),日志

## 0. 方法与证据源

1. **UI 实测**(电脑操控):标题→スタート→一级菜单→β4機能紹介→画像表示関連機能→
   フェイスウィンドウサンプル,两次会话均复现同一组症状;
2. **脚本倾倒**:`dump_game_cmds`(s136 样本本体 / s140 场景主环 / s9 es.FACE /
   s88 ES.FACE.DEFINE / s20 泵环 pc185-250 / s18 钩子 / s21 flow);
3. **内核源码读**:`vm.rs` step_command / `task.rs` 文本让出调度 /
   `vm/handlers.rs` op_word / op_returncode / `tables.rs` LabelTable;
4. **基线诊断普查**:`game_diag_probe` 2400 帧(soft 后端,无输入);
5. **直连内核探针**:会话内临时脚本(未入库;带点击时间线 + 事件流倾倒 +
   挂号表;无头菜单点击未生效,见 §5.2);
6. **用户会话控制台取证**(经翻译页间接读到的 diag 行,frame=6356 口径)。

## 1. 总判断

**不是整体架构问题。** 内核 VM 调度 / 文本让出语义与官方 REA 对齐(锚点齐全),
菜单选择、进入样本、渲染主链路均通(渲染 0 skip、missing_assets=0、script_errors=0)。
「没法玩」= 少数具体断点叠加:脚本层推进环拿到假值 + 一处 Fatal 杀任务 +
文本窗重排缺失 + 少量文本呈现缺陷。

## 2. 症状 → 机制对应

### 2.1 对话循环 / 无法推进 ✅(最核心)

- **现场**:フェイスウィンドウサンプル在「纯文本行 / 同文本+脸图」两状态间无限循环,
  到不了第 2~5 句;即用户口径「循环错误、应该显示其他表情做对比」。
- **脚本应有流程**(s136 pc0-25 倾倒):5 句 WORD + 3 次换脸
  (yuu1101→eri1001→yuu2304)→ `MAC.FOUT`/`MAC.FIN` → `es.MakeLog` →
  `es.GSD.SAVE` → `es.POSDATA.SET` → 戻る。
- **内核侧已排除**❌:`RETURNCODE` 行尾让出 = 手动模式一帧休憩后自动恢复
  (`task.rs:428` 判据 + `vm/handlers.rs:3555` op_returncode,REA
  `0x4046fc..0x404835` / `0x44c451` 锚点)。文本推进是**脚本层状态机**
  (s20 泵环 + s139/140 场景页指针)。循环 = 页指针未前进 = 推进判据拿到错误输入。

### 2.2 推进环假值来源 ⚠️(嫌疑收窄,待逐个取证)

| 查询 | 本会话(2400 帧) | 用户会话(6356 帧) | 定位 |
|---|---|---|---|
| `WINDOWINFO[DISPLAYNO]`(gfx.info.unsupported) | 556 | **24638** | es_gsd.yst SYSTEM@659 轮询环,每帧一对 |
| `FILEINFO SIZE/RELATION`(sv.command.unimplemented) | 626 | **2144** | sv@frame227(EXIST 已实现) |

若二者参与 s20 pc192-242 / s139 的分支判据,即为「循环且无提示」直接推手。
**修复期第一步**:dump 判据变量的变量身份,对号入座后再动手。

### 2.3 一处 Fatal 杀任务 ✅

- `rt.expr.div_zero` **Fatal**,es_config_font.yst pc60 LET(count=1)。
- Fatal = 任务终止(`vm.rs` step_command 错误路径;官方继续策略未取证 ⇒ DIV-RT-005)。
- 影响:設定→字体页一进即死,表现即「没法继续」。

### 2.4 文本窗重排缺失 ✅(「CG 位置不对」观感主因之一)

- 脸图位于左下**本身忠实**:ES.FACE.DEFINE 给偏移 (0,0),YU-RIS y=0 为底边
  (s88 pc4/pc5 `DEF.SET(prefix, dir, 0, 0)` → s9 pc52 `es.BT.XY.SET(@I,@J)`)。
- 实缺陷:脸图出现后消息窗矩形右移、**文本原点未随移**,开头数字被脸盖住
  (「フェイスウィンドウ…」→「…ンドウサンプルです。」)。

### 2.5 吐字卡顿 / 闪烁 / 文本无变化

- 文本无变化 / 没提示 = §2.1 的衍生(永远重放第一句)✅。
- 吐字节奏 = 每行一帧休憩(官方同,手册 basic/task.html「約0.016秒」)❌非节奏错误;
  观感卡顿疑与行级整页重绘同源(闪烁)⚠️,修复期用 `--frame-stats` 量化。

### 2.6 标题菜单「終了するる」 ✅(现象)/ ⚠️(根因)

- 多一个「る」;同引擎下级菜单「終了する」正常 → 标题画面专属的
  字符串偏移/表取值嫌疑,待查 es_title (s58)。

## 5. 工具链发现(影响取证能力)

### 5.1 非 ASCII 标签无法引导 ✅

`LabelTable::get` 仅 ASCII 等值(`tables.rs:260`「按文本查(仅 ASCII 名等值于字节查)」),
`--entry フェイスウィンドウサンプル` 报「不在工程 ysl.ybn」拒绝启动;
字节级 `get_bytes` 现成,boot 侧(`vm.rs:491-500`)未走它。

### 5.2 裸 Vm 的 InputTimeline 直驱不生效 ✅(现象)/ ⚠️(根因)

该探针按 case 跑法 `build_timeline` 同语义(f 按下、f+1 松开、光标保持,
`case.rs:303-335`)直驱 `Vm::tick_at`,菜单点击不生效;同一坐标经 Engine/case 跑法
则生效(title-config-back PASS 佐证)。Engine 与裸 Vm 之间的输入注入路径存在差异。
探针为会话内临时脚本,**未入库**;复现按本段描述直驱 `Vm::tick_at` 即可。
